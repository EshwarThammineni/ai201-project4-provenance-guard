## Detection Signals

### Signal 1: Type-Token Ratio 
- **Measures:** Vocabulary diversity minus the ratio of unique to total words.
- **Formula:** `ttr = len(set(words)) / len(words)`
- **Output:** Float between 0.0–1.0. A larger float means that there is more diverse vocabulary.
- **AI tendency:** AI generated content is more likely to produce repetitive words and generally
  produces a lower TTR score.

### Signal 2: Sentence Length Variance
- **Measures:** How much sentence vary in length.
- **Formula:** compute word count per sentence → stddev → normalize to 0–1
  by capping at a max stddev of ~15
  `variance_score = 1 - min(stddev / 15, 1.0)`
- **Output:** Float between 0.0–1.0. A high varience means it's less likely to be AI. 
- **AI tendency:** AI content tends to have a consistent sentence length. 

### Combined Confidence Score
`confidence = (signal_1_score * 0.5) + (signal_2_score * 0.5)`

Both signals are weighted equally. This can be tuned later if one
signal proves more reliable.

## Uncertainty Representation

Confidence scores represent the probability a text is likely AI. 

### Threshold Map
| Score Range  | Interpretation     | Label Assigned                        |
|--------------|--------------------|---------------------------------------|
| 0.75 – 1.00  | High AI confidence | "Likely AI generated"                 |
| 0.36 – 0.74  | Uncertain          | "Uncertain — Could not be determined" |
| 0.00 – 0.35  | High human confidence | "Likely human-written"             |

### Design rationale
The uncertain band is intentionally wide, so there is a lot of wiggle room. This reduces the chance of false postives. 

A score of 0.60 means that both signal 1 & 2 lean towards AI Generated, but aren't confident.  The label will
read "Uncertain."

## Transparency Label Design

Three label variants, written out in full:

### Variant A — High AI Confidence 
**Header:** Likely AI-Generated
**Body:** Our analysis found patterns consistent with AI-generated text.
This assessment is based on automated signals and may not be accurate.
**Confidence display:** "Confidence: [score]"
**Action prompt:** "If you believe this is incorrect, you may submit an appeal."

### Variant B — Uncertain 
**Header:** Origin Uncertain
**Body:** Our system could not confidently determine whether this text was
written by a human or generated by AI. This may reflect mixed signals,
a short text sample, or a writing style that falls outside our detection
range.
**Confidence display:** "Confidence: [score]"
**Action prompt:** "If you are the author, you may submit an appeal to
provide additional context."

### Variant C — High Human Confidence 
**Header:** Likely Human-Written
**Body:** Our analysis found patterns consistent with human-authored text.
**Confidence display:** "Confidence: [score]"
**Action prompt:** None — no appeal needed for a human-written result.

## Appeals Workflow

### Who can appeal
Any submitter who has a submission_id.

### What they provide
- `submission_id` : the ID returned at submission time
- `explanation` : free-text, up to 1000 characters

### What the system does on receipt
1. Looks up the submission record by submission_id
2. Updates the record's `appeal_status` field:
   - Before appeal: `null`
   - After appeal received: `"under_review"`
3. Writes a new audit log entry:
   `{ submission_id, event: "appeal_received", explanation, timestamp }`
4. Returns: `{ status: "received", submission_id }`

### What a human reviewer sees (appeal queue)
- Original submission text
- Original label and confidence score
- Both raw signal scores
- Submitter's explanation
- Timestamp of original submission and appeal

## Anticipated Edge Cases

### Edge Case 1: Short text (under 80 words)
TTR scores on short texts are high because almost every word
is unique by default due to the short length. It will likely return "Uncertain" for
very short inputs but users may find
it frustrating that the system can't assess a short quote or headline.

### Edge Case 3: Mixed text
A document that is 50% human-written and 50% AI-generated will produce ambiguous
results. Neither signal is designed for partial detection.

## Architecture

### Submission Flow
POST /submit
  │
  │  raw text
  ▼
Signal 1: TTR Score
  │
  │  score_1 (0.0–1.0)
  ▼
Signal 2: Sentence Variance Score
  │
  │  score_2 (0.0–1.0)
  ▼
Confidence Scorer
  │  confidence = (score_1 * 0.5) + (score_2 * 0.5)
  ▼
Label Generator
  │  ≥ 0.75 → "Likely AI-generated"
  │  ≤ 0.35 → "Likely human-written"
  │  else   → "Uncertain"
  ▼
Audit Logger
  │  { id, scores, label, timestamp }
  ▼
Response: { submission_id, label, confidence, signals }

### Appeal Flow
POST /appeal
  │
  │  { submission_id, explanation }
  ▼
Lookup record
  ▼
Update appeal_status → "under_review"
  ▼
Audit Logger
  │  { submission_id, event, explanation, timestamp }
  ▼
Response: { status: "received", submission_id }

"Using the spec below, generate a Flask app with a single POST /submit
endpoint. The endpoint should accept { 'text': '...' } and run the TTR
signal function. Return { submission_id, signal_1_score } for now —
scoring and labeling will be added in M4/M5. Use an in-memory list as
the audit log store for now."

**How to verify before wiring up:**
- Call the endpoint with a short AI-generated paragraph and a long
  human-written paragraph
- Confirm scores differ meaningfully (AI text should score lower TTR)
- Confirm the function handles empty strings without crashing
